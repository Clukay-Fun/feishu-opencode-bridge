# File Materials

Bridge 负责接收飞书上传的文件，并将其转换为 OpenCode 可以处理的格式。文件处理不是自动的——Bridge 会先问用户想怎么处理。

## 处理流程

1. 用户上传文件
2. Bridge 轻量探测（文件名、扩展名、大小）
3. Bridge 发送"你想怎么处理？"卡片
4. 用户回复处理意图
5. Bridge 进入对应 workflow / OpenCode / 知识库 / 合同助手

## 查询最近材料

当用户说"刚才那个文件""帮我总结那个 PDF""把合同审查一下"时，**必须先调用 `Bridge_recent_materials` MCP 工具**，再回答。**不要凭记忆或推测文件内容**。

返回的 `materials` 列表包含最近收到的文件元数据（文件名、类型、大小、接收时间、本地路径）。

## 处理意图示例

| 用户说 | 处理方式 |
|--------|---------|
| "总结主要内容" | 普通文件总结 |
| "审查合同风险" | 合同助手 workflow |
| "提取关键信息" | 结构化提取 |
| "收入知识库" | 知识库入库 |
| "识别发票信息" | 发票识别 workflow |

## 回答规则

- **不要重复要求用户重新上传**。Bridge 已经下载了文件，用户只需说处理意图。
- **不知道文件路径时不要编造**。先查 `Bridge_recent_materials`。
- **不要把"普通文件总结"误判成知识库入库**。只有用户明确说"入库""加入知识库"时才走知识库流程。
- **多个材料时要求用户选择**。如果 `Bridge_recent_materials` 返回多个文件，问用户"你说的是哪个？"。
